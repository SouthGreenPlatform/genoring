# AGENTS.md

GenoRing is a framework based on Perl scripts and Docker.

The `genoring.pl` script is the main script used to manage GenoRing instances.
It uses Perl libraries stored in the `perllib` directory.

- `perllib/Genoring.pm` is the main library; it loads the other libraries in the
  correct order.
- `perllib/Genoring/GenoringConst.pm` contains the constants used by GenoRing.
- `perllib/Genoring/GenoringEnv.pm` contains the environment variable
  initialization.
- `perllib/Genoring/GenoringFunc.pm` contains the GenoRing API functions.
- `perllib/Genoring/GenoringTest.pm` is only used by tests and is loaded
  independently of `perllib/Genoring.pm`.

## Modules

The `modules` directory contains the GenoRing framework modules/extensions.
A module template describing the structure of a GenoRing module is stored in
`modules/TEMPLATE`. Enabled modules provide new functionalities to a GenoRing
instance. These functionalities are provided through new Docker services,
through modifications to the volumes exposed by existing modules, or both.

## Instance directories

- The `env` directory contains the environment variables of a GenoRing instance
  and its modules.
- The `volumes` directory contains the Docker volumes exposed by a given
  GenoRing instance.
- The `dependencies` directory contains Docker Compose configuration elements
  that are loaded depending on the GenoRing running mode, also named "profiles"
  in the Docker Compose system. GenoRing uses the profiles: `dev`, `staging`,
  `prod`, `backend`, and `offline`.

## GenoRing instances

An initialized GenoRing instance has an `env` sub-directory, a `volumes`
sub-directory, a `config.yml` file containing the instance configuration, and
a `docker-compose.yml` file that orchestrates the instance services. All these
directories and files are generated automatically by `genoring.pl`. Additional
files may be present to support specific use cases:

- `extra_hosts.yml`, when services are externalized from the framework;
- `docker-compose.override.yml`, to provide manual overrides to the generated
  `docker-compose.yml` file.

Multiple GenoRing instances are possible. The default instance is stored in the
GenoRing directory (where all the directories described here are located), but
other instances can be stored in other directories with dedicated instance
files and directories (at least `env`, `volumes`, `config.yml`, and
`docker-compose.yml`). This feature is used to run tests independently from a
user instance. GenoRing instances are based on the `COMPOSE_PROJECT_NAME`
environment variable used by the Docker Compose system, and can therefore be
seen as similar to a Docker Compose "project".

## Tests

The `tests` directory contains the GenoRing test framework. The `tests/test.pl`
script manages and runs the tests. The `tests/t` directory contains the
independent tests launched by `test.pl`. The `tests/temptests` directory
contains temporary files generated by the tests (instances, logs). The
`tests/data` directory contains the static data (raw or as templates) used by
the tests.

## Main module

The main module "genoring" of the GenoRing framework provides a web interface
based on Drupal through 3 services:

- `genoring`, which contains the Drupal code part run by a php-fpm service;
- `genoring-proxy`, which contains the HTTP proxy part provided by an nginx
  service;
- `genoring-db`, which contains the Drupal database part run by a PostgreSQL
  service.
